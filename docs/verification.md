## 1. 콜드 스타트 (빈 DB에서 재현)

```
$ dropdb vdt && createdb -O vdt vdt
tables before start: 0
$ ./scripts/backend.sh start
backend up (pid 5062)
tables after start: 9
3 sessions / 3300 samples / 33000 kpi values / 45 events
```

Flyway 마이그레이션과 시드가 최초 기동 시 자동 적용됨을 확인했습니다.

> 참고(당시): `backend.sh`의 준비 확인은 API 응답 시점을 봅니다. 시드는 그 직후 완료되므로,
> 기동 직후 곧바로 DB를 조회하면 아직 0건일 수 있습니다.
>
> **이후 해소.** 컨테이너 HEALTHCHECK를 만들면서 같은 경합이 드러나 시드를
> `SmartInitializingSingleton`으로 옮겼습니다. 이제 시드가 끝난 뒤에야 웹 서버가
> listen을 시작합니다. 근거와 순서는 [`architecture.md`](architecture.md) §7.3.

## 2. API (당시 14개 엔드포인트 · 현재 43개)

전 엔드포인트 200 응답, 오류 경로도 의도대로 동작합니다.

| 확인 | 결과 |
|---|---|
| `/api/sessions` 외 13개 | 전부 200 |
| 존재하지 않는 KPI | **400** |
| 존재하지 않는 세션 | **404** |

시드 데이터의 물리적 일관성 — 지하차도 구간(seq 600) 스냅샷:

```
RSRP -119.6 dBm (CRITICAL) → SS-SINR -8.0 dB (CRITICAL) → 처리량 1.2 Mbps (CRITICAL)
CQI 1 (CRITICAL) · BLER 60% (CRITICAL) · TX power 21.5 dBm (WARNING)
```

전파가 나빠지자 링크 적응·처리량·단말 송신 전력이 **함께** 반응합니다. 값이 독립적으로 흩뿌려진 것이
아니라 서로 연동되어 있음을 보여줍니다.

## 5. 검증 중 발견하여 수정한 결함

| 결함 | 원인 | 조치 |
|---|---|---|
| 전 구간 RSRP ≥ -80 dBm | 경로 손실 식이 미터를 기대하는데 킬로미터를 대입 | 미터로 수정, 사이트 EIRP를 RE 단위로 재설정 |
| 빌드 간 SINR 차이 +12.9 dB (비현실적) | 품질 보정을 서빙 셀에만 적용해 간섭 대비가 왜곡 | RSRP 오프셋(전 셀 공통)과 수신단 SINR 개선을 분리 |
| `/distribution` 500 오류 | `open-in-view: false`에서 임계 구간이 지연 로딩 | EAGER + join fetch로 변경 |
| 리포지토리 빈 미탐지 | 중첩 인터페이스는 Spring Data 스캔 대상이 아님 | 최상위 인터페이스로 분리 |
| 지도 타일 미표시 | 샌드박스에서 브라우저의 타일 CDN 접근 차단 | 앱 결함 아님. 실패를 감지해 안내 표시 + 격자 배경으로 폴백 |
