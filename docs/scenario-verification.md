## 검증이 실제로 잡아낸 것

이 검증을 만드는 과정 자체가 결함을 찾았습니다. 기록해 둡니다.

1. **결함 창과 페이드 중첩 (데이터 결함)** — 프론트홀 주입 세션의 결함 창(seq 380–520)이
   리플레이 채널의 RSRP 딥페이드(479–501 CRITICAL)와 겹쳐 있었습니다. "무선은 정상인데
   프론트홀만 이상"이라는 시나리오의 핵심 서사가 시드 데이터에서 성립하지 않았던 것입니다.
   → RF가 깨끗한 seq 885–985로 이동. 동시에 물리를 정직하게: 수신 창을 놓친 데이터는 DU가
   폐기하므로 **처리량·PRB 사용률은 결함 창 안에서 하락**하고 RSRP/SINR/BLER은 무변.
   분류 시그니처가 "전부 정상"이 아니라 "처리량 하락 + RF 무결 → 전송로"로 바뀌어
   실제 트러블슈팅 흐름과 일치합니다.
2. **커서-디시메이션 단절 (코드 결함)** — 차트 판독값과 지도 커서가 `seq === cursorSeq`
   정확 일치로 표본을 찾아, 서버가 데시메이션한(=대용량) 세션에서 'no data'와 마커 멈춤이
   발생. 대용량 최적화가 만든 정확성 구멍이었고, 커서 이하 최근접 표본 탐색으로 수정.
3. **비교의 거짓 SAME (코드 결함)** — 한쪽 세션에 없는 KPI의 비교 판정이 SAME으로 표기.
   측정하지 않은 것과 같은 것은 다르므로 NO DATA 판정을 신설.
4. **차트 없는 KPI 12종 (도달성 결함)** — 사전 로드 6종 외 KPI 선택 시 차트가 조용히
   사라짐. 제품 차별점인 프론트홀 KPI 전부가 여기 포함되어 있었음. 온디맨드 시리즈로 수정.

6. **임계값 없는 KPI = 500 (코드 결함)** — 생성되는 `CASE` 식에 `WHEN` 가지가 없어
   `CASE ELSE -1 END`라는 구문 오류가 되었습니다. P0 "사용자 정의 KPI"를 그대로 착수했다면
   첫 화면에서 죽었을 자리입니다(상세: gap §5.4).
8. **임포트가 카탈로그를 갱신하지 않음 (도달성 결함)** — 임포트가 새 KPI를 정의해도
   파라미터 트리는 페이지 로드 시점의 목록을 계속 보여줬습니다. 사용자가 방금 살리기로 선택한
   컬럼이 화면에 없는 상태였고, S11이 잡았습니다.

7. **채워질 수 없는 구간 (설계 결함)** — 자동 비닝 1차 구현이 경계를 데이터 최댓값 위로
   반올림해 최상위 구간이 0.00%가 되었습니다. 스냅 스텝을 사다리 내 최소 간격의 절반으로
   바꿔 해결.

5. **한 번도 동작한 적 없는 엔드포인트 (코드 결함)** — 임계값 편집 UI(S9)를 붙이려는 순간
   `PUT /api/kpi-definitions/{name}/thresholds`가 유니크 인덱스 위반으로 **100% 실패**해 왔음이
   드러났습니다. 호출하는 뷰가 없었기 때문에 아무도 몰랐던 것입니다 — "로직은 있는데 뷰가 없다"가
   왜 위험한지의 실증 사례입니다. 쓰기 경로 수정과 입력 검증 신설로 해결(상세: gap §5.3).

앞의 세 검증 스크립트(`verify-ui.mjs` 30 · `verify-scenarios.mjs` 75 · `api-surface.mjs`)는
독립적으로 유지합니다: 첫째는 개별 동작 회귀, 둘째는 여정 회귀, 셋째는 "로직은 있는데 뷰가
없는" 종류의 격차를 잡습니다.
