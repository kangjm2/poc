기존 툴 분석 브리프

Nemo Analyze 10.2 User Guide 기반 · 2026-09-01

Nemo Analyze 10.2 사용자 가이드 505페이지를 1차 자료로 삼아 각 메뉴가 무엇을 하는지, 사용자가 어떤 순서로 조작하는지, 그리고 우리 구현에 어떻게 대응되는지를 정리한 브리프입니다. 각 문서는 세 부분으로 구성됩니다 — 메뉴 설명(원문 근거와 그림), 유저 시나리오(매뉴얼의 Use Case), 우리 구현에는 어떻게 반영됐는가.

브리프

문서다루는 것
① Workspace와 데이터 뷰 좌측 도크 3단 구조, 파라미터에서 나오는 질의 진입점들, 뷰 종류 전체. 우리 화면의 직접 대응물
② 분석과 드릴다운 문제 조사 파이 → 사례 그리드 → 그 순간. 영역·거리 비닝, 셀 푸트프린트, 파일럿 오염, Cell locator
③ KPI Workbench 노드 그래프 KPI 빌더의 요소 전체 명세와 UC27 실전 예제. 우리와 가장 크게 어긋난 곳
④ 워크북과 리포트 워크북·페이지·데이터뷰 3층 구조, 리포트 템플릿 3종
⑤ 판정 요약 매뉴얼과 우리 구현이 일치하는 곳과 어긋나는 곳의 판정, 그리고 다음 우선순위
⑥ 메뉴 바와 질의 API 메뉴 8개·항목 77개 전체, 단축키, 그리고 스칼라 함수 46 + 프로시저 16. 각 메뉴 항목의 자세한 설명이 있는 곳

대조표

문서다루는 것
Use Case 31개 대조표 매뉴얼의 유즈케이스 31개 전부를 한 표에서 우리 구현과 맞춰 봅니다. 브리프의 "남은 일" 표가 판단의 기록이라면, 이 표는 현재 상태의 기록입니다
⑦ Use Case 31개 상세
Markdown: use-cases.md		 매뉴얼이 각 유즈케이스에서 무엇을 하라고 하는지 — 목적·절차·원문 인용·그림 — 를 장 순서대로. 대조표가 우리 상태라면 이쪽은 레퍼런스의 내용입니다. 유즈케이스마다 필요한 입력 데이터와 우리 데이터 모델에 있는지를 명시
⑧ Use Case 요약표 31개를 설명 · 전제 · 입력 · 출력 네 열로 한 줄씩. 우리 구현과의 비교 없이 매뉴얼 내용만 간결하게 — 회의에서 훑어보는 용도
⑨ 입력 기준 분류와 사용자 시나리오 31개를 장·절이 아니라 필요한 입력 데이터로 다시 묶은 9개 그룹과, 그 묶음을 합쳐 업무의 처음부터 끝까지를 푼 시나리오 7편(드롭콜 원인 · 사이트 DB 검증 · 전후 비교 · 음성 감사 · 처리율 심층 · 5G 빔 · 자동 리포팅). 이 작업이 설계 과정의 어느 단계에 놓이는지와, 우리 E2E 검증 여정 S1–S13과의 대응표 포함

한 장 요약

매뉴얼이 우리 구현과 가장 크게 어긋난다고 확인한 곳입니다. 판정의 근거는 ⑤.

항목매뉴얼우리
State Machine 상태 점유마다 한 행 + time_interval을 출력. 기억뿐 아니라 출력 모양이 다름 더 큼 표본별 분류기
Missing neighbour 측정값만으로 판정(best active set − 1. best < 0). 설정된 이웃 목록은 쓰지 않음 생성기 막는 것은 스키마가 아니라 핸드오버 지연을 모델링하지 않는 생성기
Lee's criteria 실제 기준은 40λ — n78에서 3.4 m 이름값 미달 최소 빈 50 m
드릴다운 좌측 탭 여러 원인을 동시에 열어 두는 기능 중간 규모 스타일이 아니라 기능 격차
Weight by 지속은 시간 또는 거리(p477). 정차 시간의 가중을 빼려면 거리 가중 거리 가중 있음 1 Hz 균일이라 시간 가중은 불필요
다중 테이블 시간 상관 p480에 세 테이블을 잇는 SQL 한 문장이 있음. 평범한 조인으로 안 될 뿐 가능 상관 노드의 전제
푸트프린트 안테나 높이·틸트로 추정(p459) 두 열 cell_ref에 nullable 두 열이면 열림
Polygons Polygon region은 "run statistics over that area"(p468) — 분석 기능 기능 .TAB 자산과 달리 범위 안
우선순위 State Machine과 상관 노드는 같은 제약 하나에 걸림 — 그래프가 표본당 한 행 × 열 하나로 고정 결정 먼저 그 제약을 풀지 정하는 것이 두 항목에 앞섬
