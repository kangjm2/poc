1.2 단축키 — 16개뿐입니다 p471

일반 10개는 Ctrl+n(새 워크북)과 Ctrl+F6(다음 워크북)을 빼면 전부 표준 Windows 편집·창 명령입니다. 나머지 6개는 재생 트랜스포트입니다. 분석 기능에는 단축키가 하나도 없습니다.

우리 구현

프론트엔드에 단축키가 전혀 없습니다. ③에서 키맵이 생겼습니다. 레퍼런스가 16개이고 그중 분석 기능은 0개인데, 우리는 분석 조작에 키를 뒀습니다 — 17개 — 표본 이동(←/→/PgUp/PgDn/Home/End), 재생·속도·역방향, 커서 기준 구간 자르기([ ] \), 지도 재구성(F), Escape, 도움말(?). 이 문단이 "나아질 수 있는 자리"라고 꼽았던 바로 그 자리입니다.

같이 정한 규칙이 둘 있습니다. 하나, 키 표와 도움말이 같은 표입니다 (view/keymap.ts) — 문서와 동작이 어긋날 자리가 없습니다. 둘, Escape에 우선순위 사다리가 있습니다(모달 → 드릴다운 → 알림) — 한 번 누를 때 무엇이 닫히는지가 화면마다 달라지지 않습니다.

UC5 재방문 — 전역 필터가 왜 메뉴에 있나 p467

①에서 본 전역 필터가 Utilities 메뉴에 있는 이유가 여기서 분명해집니다. 매뉴얼의 설명이 "applied to all operations performed with Nemo Analyze" 이고, 예시로 폴리곤 영역 선택을 듭니다. 즉 지도에서 그린 도형이 앱 전체의 필터가 됩니다.

우리 구현에는 어떻게 반영됐나 2026-09-03 갱신

전역 필터가 없으므로 "이 영역만 보기"를 표현할 방법이 없습니다. 우리 대응은 파생 KPI입니다 — 다만 지금 보고 있는 화면에 즉시 걸리지는 않고, 공간 조건은 아예 표현할 수 없습니다(워크벤치가 위경도를 읽지 못하므로). 세 문장 다 지금은 틀립니다.

전역 필터는 P3에서 생겼고, 조건 두 가지가 UC5에서 그대로 왔습니다 — kpi:NAME:OP:VALUE(매뉴얼 자신의 예)와 cell:PCI ("Create Global Filter From Cell ID"). 조건은 화면을 옮겨도 남고, 필터 바가 그것을 늘 문장으로 보여 줍니다. 워크벤치도 SOURCE_SAMPLE로 위경도·속도·서빙 PCI를 읽습니다 — ⑤ C9가 "지오메트리를 못 읽음"으로 적어 둔 줄은 ⑥에서 닫혔습니다.

남은 것은 매뉴얼이 예로 든 그 입력입니다 — 폴리곤 영역을 전역 필터로 받는 경로. 도형을 그려 그 안의 통계를 내는 것은 ⑤에서 생겼고 (AreaSelection.inside), 전역 필터의 조건 문법은 kpi: · cell: · notevent: 셋이고(2026-09-04: 셋째가 ④에서 더해졌습니다) 도형은 아직 조건이 되지 못합니다. 아래 §4의 "전역 필터" 줄이 그 나머지를 가리킵니다.

3.2 진짜 격차는 개수가 아니라 확장점이 0개라는 것

우리 식 언어(KpiExpression · ColumnExpression)의 문법은 + − × ÷, 괄호, 숫자, 단항 마이너스, KPI 이름이 전부입니다. 함수 호출이라는 생산 규칙 자체가 없습니다.

그래서 위에서 "필요"로 표시한 것들 — 코드북, 정밀도 있는 동등 비교, 그리고 dB↔선형 변환(log10/power) — 을 사용자가 우회할 방법도 없습니다.

비용은 작습니다

파서는 이미 허용 목록 설계입니다 — 연산자를 하드코딩 목록과 대조하고 매칭된 상수를 출력하므로 사용자 입력이 SQL로 복사되지 않습니다. 함수 하나를 여는 것은 factor()에 분기를 더하고 이름 허용 목록을 두는 일이지 보안 모델을 바꾸는 일이 아닙니다. 그리고 이 표의 여러 칸을 한꺼번에 엽니다.

3.3 dB 평균 — 매뉴얼이 옵션으로 두고 있는 것

Options – Statistics에 "whether the dB-parameter statistics are calculated using linear math" 토글이 있습니다 p457.

우리도 읽는 사람이 고릅니다 — 2026-09-04 정정: 이 문단은 "전부 dB 도메인에서 avg()"라고 적었는데, ⑦에서 AggregationBasis가 AS_RECORDED/LINEAR를 갖고 통계 패널에 "Mean in" 셀렉트가 생겼습니다. 같은 문서 §4의 줄이 이미 ✅로 적습니다. 아래는 그때의 서술입니다: 우리는 전부 dB 도메인에서 avg() 합니다 — RSRP·RSRQ·SINR 모두. 전력의 산술 평균과 dB의 산술 평균은 같지 않고, 편차가 클수록 벌어집니다. 드라이브 테스트 관행상 dB 평균도 널리 쓰이므로 틀렸다고까지는 못 하지만, 레퍼런스는 사용자에게 고르게 하고 우리는 고정입니다. 평균에만 해당하고 min·max·백분위는 순서 통계라 영향이 없습니다.

4. 이 문서에서 남은 일로 확인된 것
