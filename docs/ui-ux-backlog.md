# UI/UX 백로그 — 순서와 근거

`docs/gap-analysis.md`와 `docs/ui-gap-vs-reference.md`가 **무엇이 다른가**를 적는 문서라면,
이 문서는 **무엇을 어떤 순서로 할 것인가**입니다. 레퍼런스와의 격차 중 **화면에 닿는 것만**
추렸고, 각 항목을 실제 코드에 대조해 확인한 뒤 순서를 매겼습니다.

## 어떻게 만들었나

| | |
|---|---|
| 후보 | 매뉴얼 정밀 조사에서 나온 검증된 발견 94건 중 UI에 닿는 것 |
| 확인 | 34개 주장을 **프론트엔드 코드에 직접 대조** — 29건 부재 확인, 5건 "부분적으로 있음", 0건 오검출 |
| 순위 | 서로 다른 세 사용자 관점이 **독립적으로** 전체 순위를 매김 |
| 종합 | 세 순위를 평균내지 않고, **갈린 지점은 "어느 작업 방식에 필요한 기능인가"로** 판정 |

세 관점은 이렇습니다.

- **베테랑** — Nemo 8년. 이 도구로 갈아타라는 말을 들었고, 클릭 한 번이 아깝습니다.
- **신입** — Nemo를 모릅니다. 뭐가 없는지 모르니, *막히지 않는가*와 *내가 틀렸을 때 알 수 있는가*만 봅니다.
- **장애추적** — "이 구간에서 전화가 끊긴다"는 민원 하나를 오늘 안에 규명해야 합니다.

## 0. 먼저 — 확인 과정이 제 주장 셋을 고쳤습니다

백로그를 쓰기 전에, 제가 앞서 적었던 것 중 **틀린 것**이 나왔습니다.

| 제가 적었던 것 | 실제 |
|---|---|
| "재생 기능이 없다" | **있습니다.** `App.tsx:88, 203–214`에 재생 루프가 있고 상태 바에 ▶/⏸가 있습니다. 진짜 문제는 다른 데 있습니다 — 아래 |
| "새로고침하면 아무것도 남지 않는다" | **과했습니다.** 사용자가 조립한 워크북은 **의도적으로 서버에 저장**되고 실제로 살아남습니다(`V9` 주석과 `verify-ui.mjs:643`이 그걸 단언합니다). 사라지는 것은 **뷰 상태**입니다 |
| "단축키가 하나도 없다" | 앱 코드에는 없지만 **Leaflet 자체 키보드 핸들러는 켜져 있습니다** |

### 재생의 진짜 결함은 "없음"이 아니라 **해상도**입니다

```js
const stepSize = Math.max(1, Math.round(maxSeq / 240))   // App.tsx:207
```

재생은 주행 길이와 무관하게 **항상 240스텝**입니다. 1분 안에 전체를 훑겠다는 의도는
합리적이지만, 결과적으로 **2시간 주행(약 7,200표본)에서는 30표본씩 건너뜁니다.**
30개 중 29개에는 커서가 **영원히 닿지 않습니다.**

> 1 Hz 균일 샘플이라 "다음 표본"이 정확히 정의되는데도 그렇습니다.
> **모델의 한계가 아니라 UI의 양자화 선택**이고, 그래서 고칠 수 있습니다.

## 1. 순서

### ① 증거 무결성 — 도구가 **틀린 답을 자신 있게** 내놓는 곳 `s`

세 관점이 **거의 같은 문장으로** 지목한 유일한 항목입니다.
베테랑 *"내가 거짓을 발표하게 만드는 유일한 항목"*, 신입 *"내가 틀렸다는 걸 알려주지 않는 유일한 구멍"*,
장애추적 *"느린 답이 아니라 틀린 답을 주는 유일한 항목"*.

| 항목 | 지금 무슨 일이 일어나나 |
|---|---|
| **경로선이 결측 구간을 잇습니다** | 90초 터널 구간이 건물 사이를 지나는 **직선 한 줄**로 그려지고, 툴팁도 평범한 커버리지처럼 붙습니다 → **차가 측정한 적 없는 길에 커버리지 홀을 표시하게 됩니다** |
| **GPS 튐에 방어가 없습니다** | 잘못된 좌표 하나가 바다까지 갔다 오는 스파이크를 그리고 **주행 거리에 1 km를 조용히 더합니다** |
| **임포트가 중복 이름을 막지 않습니다** | `drive_0412`가 두 개 생기고, 두 주 뒤에 **엉뚱한 주행을 10분간 분석**하게 됩니다 |

> 뒤에 오는 **모든 거리 기반 통계의 전제**이기도 합니다. 가짜 1 km가 들어간 거리 값 위에
> 거리 가중 평균을 얹으면 오염이 전파됩니다.

### ② 이벤트의 시각 채널 `s`~`m` — 순위 1 / 4 / 1

**아무도 이 클러스터에서 무엇 하나 미루지 않았습니다.** 더 결정적인 것은,
세 관점이 **서로 다른 항목**을 각자의 최우선으로 꼽았다는 점입니다 — 지도 마커, 차트 주석,
전후 맥락 창. 하나짜리 기능이 아니라 **한 능력을 세 각도에서 본 것**이므로 통째로 내야 합니다.

1. **이벤트 타입 레지스트리** `m` — 타입·표시명·아이콘·색을 테이블로.
   지금은 같은 실패가 Events 독에서는 `RADIO_LINK_FAILURE`, 파이 차트에서는 `Radio link failure`입니다
2. **지도에 타입별 심볼** `s` — *"RLF 6건이 같은 거리에서 났나"* 가 6번 클릭 + 암기에서 **한 눈**으로
3. **차트에 이벤트 마커** `s` — *"RLF가 처리량 붕괴보다 먼저였나 6초 뒤였나"* 를 답할 유일한 길
4. **드릴다운에 전후 맥락 창** `m` — 커서만 움직이는 대신 사건 전후 구간을 고정 폭으로

### ③ 기본 조작 표면 `s` — 순위 4 / 2 / 2, 장애추적의 최악 항목

두 종류의 실패가 한 클러스터에 있습니다. **그 순간에 도달할 수 없고**(커서),
**그 순간을 붙잡거나 남에게 건넬 수 없습니다**(상태·URL·줌).

1. **표본 단위 커서** `s` — 화살표 키로 한 표본씩, 스텝 버튼, 재생 **속도** 조절과 역방향.
   위 §0의 30표본 건너뛰기가 여기서 닫힙니다
2. **뷰 상태를 URL에** `s` — 세션·KPI·seq·빈 크기·탭·지도 시점.
   새로고침 복구와 **링크 공유가 한 번에** 해결됩니다. 세 관점 모두 *"증거를 넘기는 방식"*으로 이걸 꼽았습니다
3. **Esc로 모달 닫기 + 최소 키맵** `s`
4. **파라미터를 바꿔도 지도 줌 유지**, 패널 간 시점 연동 `m`

> ✕ **우클릭 컨텍스트 메뉴는 미룹니다.** 장애추적은 원하고, 베테랑은 무덤덤하고,
> 신입은 *"어차피 발견 못 합니다"* 라며 거부합니다. **신입의 진단이 정확합니다** —
> 셋 다의 진짜 불만은 *범위 좁히기 컨트롤이 화면 맨 아래 상태 바에 있는데 눈은 지도에 있다*는 것입니다.
> **컨트롤 위치를 고치고 제스처는 나중에.**

### ④ 색상 시스템 — **진단용 절반만** `s` — 순위 3 / 6 / 3

순위가 갈린 선을 따라 클러스터가 정확히 둘로 쪼개집니다.

1. **범례 구간 클릭 → 지도에서 그 구간만** `s` — 세 관점 **전원**이 지목.
   지금 우회로는 *색상 편집기를 열어 나머지 구간을 회색으로 칠하고, 보고, 되돌리기*
2. **범주형(값 동일성) 색칠** `l` — 첫 대상은 **서빙 PCI로 경로선 칠하기**.
   핸드오버 경계가 지도에 한 눈에 드러납니다. ②의 이벤트 타입 팔레트를 재사용

> ✕ **미룹니다**: 이름 붙은 재사용 가능 색상셋 `m`, 색상셋 카탈로그 뷰 `s`,
> 그리드/Numerical Data를 스케일 색으로 칠하기 `xs`, 그리드 열별 색 바인딩 `m`,
> 셀 마커를 값으로 칠하기 `s`.
>
> 신입이 이 클러스터를 6위로 놓은 이유가 *"핸드오버 경계를 못 본다는 걸 누가 보여주기 전엔 요청할 생각도 못 했을 것"* 입니다.
> **초보가 문제를 아직 못 봐서 낮게 매긴 것은 항목에 대한 반증이 아닙니다** — 그래서 진단용 절반은
> 경험자 두 명 쪽으로 판정합니다. 반대로 **관례 관리용 절반은 신입의 낮은 순위가 유효한 증거입니다**:
> 그 절반은 사용자에게 *이미 관례가 있을 때* 값이 생기니까요.

### ⑤ 공간 조작 — 나머지 `m` — 순위 2 / 3 / 4

1. **지도에 임의 폴리곤 → 그 영역 통계** `m` — 민원은 **시간이 아니라 도로 구간**으로 옵니다.
   지금은 그 구간을 세 번 지났다면 `Mark from`/`Mark to`를 세 번 반복하고 **합칠 수도 없습니다**
2. **두 세션의 공간 차분 지도** `m` — 지금은 *"B가 2.1 dB 나쁨"* 까지만 알고,
   한 거리가 나쁜 건지 전체가 나쁜 건지 보려면 **스크린샷 두 장을 번갈아 봅니다**

### ⑥ 워크벤치 — 셋 중 **한 조각만** — 순위 1 / 5 / 6 (가장 크게 갈린 곳)

**"만드는 사람 대 보는 사람"의 차이**입니다. 평균내면 안 됩니다.

1. **`SOURCE_SAMPLE` 노드** `s` — 위경도·속도·서빙 PCI를 캔버스로.
   **세 관점 전원이 원하고**, 둘은 **같은 예시 KPI 두 개**를 댔습니다
   (*"움직이는 동안의 RSRP 마진"*, *"PCI 41이 서빙일 때의 BLER"*). 두 명이 클러스터를 최하위로 매긴 곳에서 나온 만장일치
2. **`SOURCE_EVENT` 노드** `m` — ②의 레지스트리 위에
3. **중간 노드 결과 미리보기** `m` — 행 수 + 표본 행. **발행 없이, 카탈로그 등재 없이**

> **③의 미리보기를 신입 개인의 불편으로 보면 순위를 잘못 매깁니다.**
> 지금 우회로는 *KPI 이름을 지어내 발행 → 전 세션에 행을 쓰고 카탈로그에 모두가 보는 항목을 추가 →
> 다른 화면에서 확인 → 돌아와 삭제*이고, 이걸 **추측할 때마다** 합니다.
> 즉 **가장 경험 없는 사용자가 공유 상태를 매 시도마다 변형**합니다. 개인 불편이 아니라 **다중 사용자 무결성 문제**입니다.

> ✕ **미룹니다**: 재사용 부분 그래프(Components)와 이름 붙은 상수 `l` —
> **세 관점 전원의 "안 해도 됨" 목록**에 있고 클러스터에서 가장 큰 항목입니다.
> ✕ **생성 SQL 패널** `xs` — 셋 중 둘이 *"읽지 않겠다"* 고 명시했습니다.
> 그 밑의 진짜 요구(*"Combine이 내가 의도한 척추로 조인했나"*)는 **미리보기가 더 잘 답합니다.**
> SQL 패널 대신 미리보기에 **행 수와 조인된 표본 행**을 넣습니다.

### ⑦ 통계·분포 화면 — 순위 5 / 5 / 6

**일관되게 낮지만, 낮은 이유가 셋 다 다릅니다.** 아무도 막히지 않고, 대신
**틀렸다는 걸 알 방법 없이 틀린 숫자를 제출하게** 됩니다. 늦은 자리가 맞지만 빠질 자리는 아닙니다.

1. **기준과 도메인을 표기** `xs` — 하드코딩된 `[Sample]` 범례 머리글을 풀고,
   평균에 **"dB 도메인"** 을 명시. 통계 패널·리포트·내보내기 전부
2. **거리 기준 집계를 선택 가능한 기준으로** `l` — 표본 기준은 기본값 유지.
   빌드 비교의 **판정을 바꾸는** 정차 편향이 여기서 사라집니다. **①의 GPS 방어 이후에**
3. **선형 도메인 평균을 별도 이름의 옵션으로** `m` — **절대 기본값이 아니고, 절대 조용히 바꾸지 않음**

> dB 평균은 **삼자 대립**입니다. 베테랑은 반대(*"내 숫자가 남들과 어긋납니다"*),
> 신입은 조용히 고쳐지길 원하고, 장애추적은 티켓용으로 필요합니다.
> **계산 요청이 아니라 표기 실패입니다** — 라벨을 먼저 붙이면 세 입장이 동시에 만족됩니다.

> ✕ **미룹니다**: 구간 경계 포함 방향 `m` (셋 다 낮게 봤고 둘이 같은 우회로를 제시 — *"-100.1을 치고 넘어간다"*),
> 밀도(PDF)와 사용자 지정 구간 `m`.

### ⑧ 세션·워크스페이스 관리 — 순위 **7 / 7 / 7** (만장일치 최하위)

> ⚠ **이 만장일치는 표본 편향입니다.** 세 관점 모두 주행을 **받는** 사람이고,
> **임포트하는 사람이 없습니다.** *"테스터의 고통이지 내 것이 아니다"* 라는 말이 세 번 나옵니다.
> 미루되, **세 명이 반대해서가 아니라 그 사람에게 아직 안 물어봤기 때문**이라고 적어 둡니다.

- 임포트 진행률(행 수)과 **작동하는 취소** `m`
- 폴더 통째로 로드 + 장비·사업자·기술 값 **임포트 간 유지** `s`
- 세션 목록 검색·필터(날짜·장비·사업자·지역) `s`

> ✕ Projects(저장된 세션 집합) `m` — 캠페인 관리. 베테랑은 8년간 머릿속에 담아 왔습니다.

## 2. 싼 것부터 — 큰 덩어리 뒤에 줄 세우지 말 것

전부 `xs`~`s`인데 효과가 큽니다. **클러스터 순서와 무관하게** 먼저 할 수 있습니다.

| # | 항목 | 크기 | 왜 |
|---|---|---|---|
| 1 | 경로선의 결측 구간을 **끊어서** 그리기 + GPS 튐 방어 | `s` | 백로그에서 **유일하게 "거짓을 발표하게 만드는"** 항목 |
| 2 | 지도에 **이벤트 타입별 심볼** | `s` | 베테랑의 최악 항목. 6클릭+암기 → 한 눈 |
| 3 | 차트에 **이벤트 마커** | `s` | *"먼저였나 나중이었나"* 를 답할 유일한 길 |
| 4 | **범례 구간 클릭** → 지도에서 격리 | `s` | 세 관점 전원 지목 |
| 5 | **표본 단위 커서**(화살표·스텝·속도) | `s` | 1초짜리 사건을 **선택 가능하게** 만듦 |
| 6 | **뷰 상태를 URL에** | `s` | 새로고침 복구 + 링크 공유가 한 번에 |
| 7 | **Esc로 모달 닫기** + 최소 키맵 | `s` | 사소하고, 전원이 부딪힘 |
| 8 | **`SOURCE_SAMPLE` 노드** | `s` | 두 명이 최하위로 매긴 클러스터에서 나온 **만장일치** 항목 |
| 9 | 임포트 **중복 이름 감지 + 설명 필드** | `s` | 최하위 클러스터에서 **유일하게 "잘못된 증거" 사례**가 있는 항목 |
| 10 | `[Sample]` **하드코딩 해제** + 도메인 표기 | `xs` | 계산을 안 바꾸고 dB 삼자 대립을 해소 |

## 3. 세 관점이 합의한 것

- **세션 관리가 꼴찌** (7/7/7) — 다만 위 ⑧의 표본 편향 단서와 함께 읽을 것
- **경로선의 거짓** — 유일하게 세 명이 거의 같은 문장으로 지목
- **이벤트 클러스터에서 아무것도 미루지 않음** — 그리고 각자 **다른 항목**을 최우선으로
- **커서가 필요한 표본에 닿지 않음** — 셋이 독립적으로
- **새로고침 손실과 공유 불가** — 셋 다 *"증거를 넘기는 방식"* 이라는 같은 2차 영향을 지목
- **범례 구간 클릭** — 색상에 무관심한 신입까지 포함해 전원
- **그래프가 위경도·속도·PCI를 못 읽음** — 전원, 그리고 둘이 같은 예시 두 개
- **만장일치 보류 셋**: Components/상수(`l`), 색상셋 카탈로그, 지도 거리 측정

|---|---|---|---|---|

셋 중 신입만 **산출물을 만들라는 요구**를 받는 사람이고, 나머지 둘은 매일 지도를 보되
KPI는 2주에 한 번 만들거나 아예 안 만듭니다. 평균내면 둘 다 틀립니다.

| 이름 붙은 재사용 색상셋 `m` | 사용자에게 **이미 관례가 있을 때** 값이 생깁니다. 아직 이릅니다 |

## 6. 이 문서 밖에 있는 UI 항목

브리프의 "남은 일" 표에서 나왔지만 위 7개 클러스터에 안 들어간 것들입니다.
크기가 작고 독립적이라 위 순서에 끼워 넣기 쉽습니다.

| 항목 | 크기 | 어디에 붙일까 |
|---|---|---|
| **드릴다운 다중 탭** (조각 색 유지) | 중 | ② 뒤 — 여러 원인을 동시에 열어 두는 기능 |
| 파라미터 **★ 즐겨찾기** | 매우 작음 | ③과 함께 |
| 사용자 KPI의 **출처 표시**(`User` 분류) | 작음 | ⑥의 미리보기와 함께 — 발행된 KPI의 출처가 보여야 |
| **전역 필터** | 중 | ⑤ 폴리곤 뒤 — 폴리곤이 전역 필터의 첫 입력 |
| **color grid · surface** 차트 | 중 | ⑦ 뒤 — 두 파라미터 상관을 보는 유일한 뷰 |
| 워크북 **레이아웃 프리셋** · 기성 워크북 **복사** | 작음 | 독립 |
| 리포트 **구성 선택** · 워크북 **PDF/이미지** 내보내기 | 중/작음 | 독립 |
