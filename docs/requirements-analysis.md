# 기존 솔루션 요구사항 분석 및 대체 설계

**대상**: Keysight Nemo Outdoor / Nemo Analyze 사용자
**목표**: 기존에 쓰던 기능을 **동등하게** 제공하면서, 기존 도구가 주지 못하던 **인사이트를 추가**한다.
**근거**: [`keysight-vdt-research.md`](./keysight-vdt-research.md), [`assets/`](./assets/)의 공식 PDF·스크린샷

---

## 1. 전략

기존 사용자를 옮겨오려면 두 가지가 동시에 필요합니다.

| 축 | 내용 | 실패 시 결과 |
|---|---|---|
| **기능 동등성** | 매일 쓰던 화면·조작이 그대로 있을 것 | "이걸로는 내 일을 못 한다" → 전환 거부 |
| **전환 이유** | 기존 도구에 없던 가치 | "굳이 왜 바꾸나" → 전환 동기 없음 |

### 1.1 반드시 보존해야 할 3가지 (기존 UX의 정체성)

리서치에서 확인한, Nemo 사용자가 **몸으로 익힌** 상호작용입니다. 이걸 깨면 아무리 좋아도 거부당합니다.

1. **공유 시간 커서** — 모든 그래프·그리드·지도가 하나의 시각을 가리킴. 커서를 옮기면 전 패널의 값이 동시에 바뀜
2. **워크북 탭** — 사용자가 구성한 화면 세트를 하단 탭으로 전환 (`5G NR key measurements`, `LTE L1`, `Map` …)
3. **임계 강조** — 그리드 셀이 임계 초과 시 적색, 경고 시 황색으로 **배경 전체가** 칠해짐

### 1.2 의도적으로 다르게 갈 부분

| 항목 | 기존 | 대체 | 이유 |
|---|---|---|---|
| 배포 형태 | Windows 설치형 | **웹** | 설치·라이선스 서버 불필요, 협업 가능 |
| 데이터 접근 | 로컬 파일 DB | **PostgreSQL 서버** | 다중 사용자, 세션 간 비교 |
| 브랜딩 | Keysight/Nemo | 자체 | 상표 회피 (`assets/NOTICE.md`) |

## 3. 추가 기능 — 전환의 이유

기존 도구에 **없거나 약한** 부분을 겨냥합니다.

| ID | 기능 | 근거 |
|---|---|---|
| **NEW-01** | **자동 열화 구간 탐지** — KPI가 임계 이하로 떨어진 구간을 자동 추출해 목록화 | 기존은 사람이 그래프를 눈으로 훑어야 함 |
| **NEW-02** | **세션 A/B 비교 뷰** — 두 세션의 동일 KPI를 한 화면에 겹쳐 표시 + 통계 차이 | `[AN]` 벤치마킹은 있으나 무겁고 워크북 구성 필요 |
| **NEW-03** | **KPI 임계값 서버 저장 + 편집 UI** — 사업자별 기준을 서버에 두고 전 사용자 공유, 범례에서 직접 편집(경계 사다리 방식) | 리서치 §6.4: CSSR/DCR/HOSR은 3GPP가 아닌 **사업자 관행**이므로 설정 가능해야 함. 구현·검증: gap §5.3, 시나리오 S9 |
| **NEW-04** | **구간별 분포 요약** — 범례가 곧 통계 (구간별 건수·비율) | `[AN]`의 Color Legends를 기본 동작으로 승격 |
| NEW-05 | 웹 링크로 세션 공유 | 설치형에는 불가능 |

## 5. 시각 디자인 사양

리서치 §11.3에서 확정한 값입니다.

### 5.1 KPI 색상 스케일 (Nemo 공식 범례와 동일 구조)

| 구간 | Hex | 의미 |
|---|---|---|
| `>= -80` | `#009300` | 양호 |
| `< -80 and >= -90` | `#FFFF00` | 보통 |
| `< -90 and >= -100` | `#FF6820` | 미흡 |
| `< -100` | `#FF0000` | 불량 |

범례에는 **반드시 구간별 샘플 수와 비율**을 함께 표시합니다. 범례 제목은 참조 도구가 쓰는
3요소 형식(`KPI (단위) [가중 기준]`)을 따릅니다 — 우리는 표본 가중이므로 `[Sample]`로 표기합니다.

KPI별 구간 경계와 그 근거는 리서치 §11.3.4에 정리했습니다. 요약하면 RSRP(-80/-90/-100)와
SS-SINR(0/5/15)은 독립 출처 2종(AOSP 기본 캐리어 설정, AZQ 드라이브 테스트 테마)과 교차 확인되었고,
DL 처리량은 50/100/300으로 정정(기존 하한 20은 무근거), RSRQ는 출처 간 편차가 커 자체 기본값입니다.

## 6. 데이터 모델

```
measurement_session  세션 (단말, 사업자, 기술, 시작/종료)
cell_ref             셀 (PCI, ARFCN, band, GSCN, 위경도, 방위각)
sample               시계열 샘플 (ts, 위경도, serving_cell)
sample_kpi           샘플별 KPI 값 (sample_id, kpi_name, value)  ← 좁은(narrow) 스키마
kpi_definition       KPI 정의 (이름, 단위, 카테고리, 방향)
kpi_threshold        구간 정의 (kpi, 하한, 상한, 색상, 라벨, 순서)
network_event        이벤트 (ts, 유형, 상세)
signaling_message    L3/RRC 메시지 (ts, 방향, 프로토콜, 메시지명, 본문)
```

`sample_kpi`를 **좁은 스키마**로 두는 이유: 리서치 §6.2에서 Nemo가 *"4,000가지 이상의 L1–L3 KPI 통계"* 를
다룬다고 확인했습니다. 넓은(wide) 테이블로는 감당할 수 없습니다.

## 7. POC 범위와 검증 기준

**포함**: FR-01~03, 10~18, 30~35, 40, 50, 52~53, NEW-01~04
**제외**: 로그 임포트, 3D, area binning, 리포트 생성, 도킹 자유 배치

**검증 기준** — 아래가 실제로 동작함을 보인다.

1. PostgreSQL에 현실적인 드라이브 테스트 데이터가 적재된다
2. Spring Boot API가 세션·샘플·KPI·이벤트·통계·비교를 응답한다
3. React UI에서 지도에 경로가 **색상 구간별로** 그려지고 범례에 비율이 나온다
4. 시간 커서를 움직이면 그래프·그리드·지도가 **함께** 갱신된다
5. 임계 초과 셀이 적색으로 강조된다
6. 워크북 탭으로 화면 세트가 바뀐다
7. 두 세션 비교가 통계 차이를 보여준다
8. 자동 열화 구간 탐지가 결과를 반환한다
